# MagicPodcast 全站性能优化方案

最后更新：2026-05-18

## 目标

让 `https://rookiestar.cn/` 的核心页面稳定打开，不再出现首页一直加载、列表首屏自动多拉数据、详情页图片过大、页面切换时额外请求过多等问题。

本轮完成标准：

- 首页、播客列表、播客详情、标签、导入、工作流列表、工作流详情均能正常渲染。
- 首屏不再因为默认预加载产生大量无效请求。
- 播客列表首屏只加载第一页，用户滚动后才继续加载。
- 工作流详情页不再一次性加载大量大图。
- 构建、类型检查、单元测试、健康检查、公开域名抽查都通过。

## 本轮诊断

| 页面 | 主要问题 | 本轮处理 |
| --- | --- | --- |
| 首页 | 入口卡片默认预加载 4 个页面，产生多余请求和中断请求 | 关闭首页入口卡片预加载 |
| 播客列表 | 首屏会提前触发第 2 页加载；封面尺寸声明过宽，容易拉大图 | 继续加载改为滚动后触发；修正封面尺寸 |
| 播客详情 | 标签编辑组件在页面打开时就拉取全部标签，移动端和桌面端会重复请求 | 改为聚焦编辑时再加载，并共享同一次请求 |
| 标签页 | 列表跳转详情时会触发默认预加载 | 关闭高密度列表链接预加载 |
| 导入页 | 页面本身较轻，主要受全局导航预加载影响 | 关闭全局导航默认预加载 |
| 工作流列表 | 每张卡片的详情链接会触发默认预加载 | 关闭列表详情链接预加载 |
| 工作流详情 | 指定节目较多时，概览页一次性展示大量节目封面，并触发大图下载 | 概览只展示前 12 个节目；缩略图走统一封面组件和小尺寸加载 |
| 搜索侧边栏 | 展示、跳转、数量统计、空结果保护分散在组件中，容易产生边界崩溃 | 拆出可测试逻辑，缺少某类结果数组时也能稳定显示 |

## 已落地改动

- 全局导航、首页入口卡片、高密度列表链接默认不再做页面预加载。
- 播客卡片封面尺寸声明修正，避免首屏拉取远大于实际展示尺寸的图片。
- 播客列表继续加载改为用户滚动后触发，避免首屏自动请求下一页。
- 播客详情页的单集缩略图改为固定小尺寸优化地址，避免小图下载原始大图。
- 工作流详情页的指定节目概览限量展示，剩余节目入口转到配置页查看。
- 工作流详情页节目缩略图改用统一封面组件，按小图尺寸加载。
- 标签编辑的可选标签列表改为按需加载，并共享缓存，避免重复请求。
- 搜索侧边栏展示逻辑、链接构建、结果数量、展开按钮、缺失数据兜底拆成可测试逻辑。

## 后续优化路线

### 阶段 1：继续压首屏请求

目标：每个页面只请求当前屏真正需要的数据。

- 播客详情页：检查封面原图来源，对大图做更严格的尺寸和缓存控制。
- 工作流详情页：执行历史、配置详情按标签页延迟加载。
- 标签页：标签下节目列表只在展开或进入详情时加载更多信息。
- 搜索侧边栏：结果预览保持轻量，进入详情页再补充完整内容。

完成标准：

- 首页保持 10 个左右请求。
- 轻量页面请求数稳定在 15 个以内。
- 详情页首屏只加载当前标签页需要的数据。

### 阶段 2：减少接口返回体积

目标：接口返回“够用”的数据，不把详情页暂时用不到的大字段提前发到前端。

- 播客列表接口返回精简字段，长简介和完整元数据留到详情页。
- 工作流列表接口返回摘要字段，执行详情和报告内容留到详情页或弹窗。
- 搜索接口区分结果预览和完整详情，减少长文本片段体积。
- 单集列表接口继续保持分页，避免一次性返回大量 show notes。

完成标准：

- 列表页接口体积可解释、可控。
- 详情页只有用户明确进入或展开时才获取大字段。

### 阶段 3：图片策略统一

目标：所有封面、缩略图、富文本图片都有统一尺寸、缓存和兜底策略。

- 将工作流、搜索、单集卡片里剩余的普通图片逐步接入统一封面或图片代理。
- 大图只在需要看清内容时加载，小图只用小尺寸。
- 对外部图片失败、慢响应、缺少尺寸的情况统一兜底。

完成标准：

- 列表和概览页面不再下载原始大图。
- 图片失败不影响页面主体渲染。

### 阶段 4：长期观测

目标：后续改动不会悄悄把性能拉回去。

- 固化 7 个核心页面的性能冒烟检查。
- 每次发布前记录请求数、失败请求、首屏是否完成渲染。
- 对首页卡住、列表重复加载、详情页大图突增建立检查项。

完成标准：

- 性能回归能在发布前发现。
- 后续优化有固定基线，不靠主观感受判断。
