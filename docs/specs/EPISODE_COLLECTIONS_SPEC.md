## Problem Statement

用户希望把小宇宙编辑整理的单集清单带入 MagicPodcast，保留专题、原始顺序和逐集推荐语，挑出值得投入的一集继续处理。目前个人播客库及常用抓取流程主要围绕已关注内容，缺少完整的外部清单入口和逐集采纳路径。

代码并非只能接收关注来源，已有指定节目与自定义 RSS 的工作流范围；问题是外部发现资料与个人库的边界没有覆盖清单单集。直接把整份清单写入个人节目和单集存储，再标记为未关注，仍会扩张个人搜索和节目列表；父节目已关注时，清单新收录的单集还可能意外进入最近更新或报告。

用户不希望为了留下一集而关注整档节目、抓取所有历史单集或自动启动加工；也不希望丢失原清单的策展上下文。

## Solution

引入独立的“播客清单”：粘贴小宇宙单集清单链接，预览并保存清单；完整浏览其单集、推荐语和 Show Notes；选中一集时，去重后收录并加入 Inbox。进入 Focus 后继续使用既有深度处理流程。

五项已确认的产品选择：仅单集清单、指定链接导入、按需收录、手动刷新并展示变化、选中后默认收录并加入 Inbox。

在首页 Discovery 标题下、现有筛选项上方增加“播客清单”入口；列表、详情和导入弹窗沿用当前产品样式。清单独立保存，不混入工作流最近更新。关注所属节目、整档同步和进入 Focus 仍是独立动作。

## User Stories

1. As a MagicPodcast 用户, I want 从首页 Discovery 下直接打开播客清单, so that 我能找到新功能而无需记住地址。
2. As a 手机用户, I want 在首页首屏找到同一清单入口, so that 我不需要在桌面上完成发现操作。
3. As a 清单浏览者, I want 看到已导入清单的主题、简介、来源及单集数, so that 我能选择值得浏览的专题。
4. As a 清单浏览者, I want 按清单标题搜索并能清空恢复列表, so that 我能找到已保存的清单。
5. As a 首次使用者, I want 在没有清单时看到明确的导入操作, so that 我知道如何开始。
6. As a 清单导入者, I want 粘贴小宇宙单集清单链接并预览, so that 我能确认导入对象。
7. As a 清单导入者, I want 预览标题、作者、已读取条目及原始推荐语, so that 我能确认内容与原清单一致。
8. As a 清单导入者, I want 在提交前取消或修改链接, so that 误贴链接不会产生不需要的清单。
9. As a 清单导入者, I want 保存我刚刚确认的那份预览, so that 提交时不会悄然变成另一版清单。
10. As a 清单导入者, I want 重复导入时打开已有清单, so that 不会创建副本或覆盖个人选择。
11. As a 清单导入者, I want 导入清单不改变个人库、订阅和 Inbox, so that 我可以低成本浏览尚未决定采纳的内容。
12. As a 清单浏览者, I want 保留原清单顺序和每条推荐语, so that 我能理解策展者为何推荐这一集。
13. As a 清单浏览者, I want 清楚区分推荐语、Show Notes 和个人状态, so that 不会把来源表述当成我的备注或系统生成结论。
14. As a 清单浏览者, I want 看到单集标题、节目、封面、时长和发布日期, so that 我能判断内容和投入成本。
15. As a 清单浏览者, I want 查看尚未入库单集的公开 Show Notes, so that 我能先了解内容再决定采纳。
16. As a 清单浏览者, I want 通过“小宇宙链接”打开原清单, so that 我能核对来源或继续在源站浏览。
17. As a 清单浏览者, I want 看到“作者：”对应的源清单作者, so that 我知道是谁组织了这份清单。
18. As a 清单浏览者, I want 在具体条目中打开原单集, so that 我可以使用源站提供的内容能力。
19. As a 清单浏览者, I want 从“全部／未收录／已收录”筛选条目, so that 我能继续上次的筛选过程。
20. As a 内容筛选者, I want 点击“加入 Inbox”只收录这一集, so that 未选中的单集不会占用个人库和注意力。
21. As a 内容筛选者, I want 收录成功时同时看到正确的 Inbox 状态, so that 不会遇到“显示成功但队列里找不到”的结果。
22. As a 内容筛选者, I want 重复点击或在多份清单采纳同一集时复用已有单集, so that 不会产生重复内容。
23. As a 内容筛选者, I want 已有 Focus、Someday、Done 或不感兴趣状态不被重复收录改写, so that 先前决定仍然有效。
24. As a 内容筛选者, I want 收录一集后所属节目保持原关注状态, so that 我无需接受整档节目更新。
25. As a 个人库使用者, I want 看到“未关注 · 已收录 N 集”并区分本地数量和源站总数, so that 我不会误以为整个节目已经同步。
26. As a 个人库使用者, I want 只在个人搜索中找到明确收录的内容, so that 浏览过的库外清单不会污染搜索。
27. As a 个人库使用者, I want 已采纳内容显示来自哪份清单, so that 我可以回到发现它的上下文。
28. As a 内容处理者, I want 将采纳的单集移入 Focus 后使用现有加工流程, so that 我不需要学习另一套清单加工机制。
29. As a 节目关注者, I want 后续 RSS 同步识别已从清单收录的同一集, so that 笔记、队列和加工产物仍属于同一单集。
30. As a 工作流使用者, I want 清单独有单集不意外进入最近更新和日报, so that 原来的内容范围不被悄然扩大。
31. As a 清单维护者, I want 主动刷新并看到新增、移出、重排及推荐语变化, so that 我能决定是否更新本地清单。
32. As a 清单维护者, I want 刷新新增的条目仍保持未收录, so that 来源更新不会替我作出采纳决定。
33. As a 清单维护者, I want 源清单移出某集时保留已收录内容和个人状态, so that 外部编辑不会删除我的积累。
34. As a 清单维护者, I want 删除本地清单后保留已经收录的单集, so that 整理清单不会删除笔记和产物。
35. As a 个人库使用者, I want 删除单集后不会因刷新清单被自动恢复, so that 删除决定受到尊重。
36. As a 清单使用者, I want 遇到网络慢或失败时保留已成功保存的内容, so that 我仍能浏览并稍后重试。
37. As a 清单使用者, I want 区分来源受限、解析不完整和真正空清单, so that 我不会被错误结果误导。
38. As a 清单使用者, I want 身份冲突时得到明确提示而不是自动猜测合并, so that 不相关单集不会共享个人数据。
39. As a 多页面使用者, I want 并发刷新或收录不会互相覆盖, so that 我的操作结果稳定可解释。
40. As a 键盘和手机用户, I want 弹窗可关闭、主按钮可见、页面不横向溢出, so that 我能完整完成导入和收录。
41. As a 清单使用者, I want 复制地址、刷新和前进后退仍能定位清单及条目, so that 我不会因导航丢失阅读位置。
42. As a 清单使用者, I want 页面只保留与浏览和操作有关的信息, so that 冗余产品说明不会干扰内容判断。

## Implementation Decisions

### 1. 领域与边界

- 沿用 ADR 0003 的“发现候选与个人播客库分离”原则，将外部单集引用纳入候选语义；实施时同步补充领域词汇中“发现候选池”和“入库”的单集边界，不把所有候选写入个人库。
- 单集清单是围绕主题、带顺序及推荐语的一组单集引用。清单条目是某集在某份清单中的位置、推荐语和外部身份。同一集可以属于多份清单。
- 导入、浏览、页面打开和刷新均不自动关注节目、不启动完整节目同步、不下载全部音频、不执行模型或转写。
- 首版唯一采纳主操作是“加入 Inbox”，不增加“仅收录”和“整份收录”按钮。新采纳且无已有行动状态的单集进入 Inbox；存在其他状态时，先显示原状态，重新处理等继续使用既有显式操作。
- 首版不新增整档自动同步开关。主动关注节目或将节目加入指定工作流属于独立操作；相应界面说明其整档范围，不能从收录单集推导授权。

### 2. 最终界面合同

| 界面 | 固定行为和文案 |
| --- | --- |
| 首页 | 在左侧 Discovery 标题及周期说明下、现有筛选项上方放置“播客清单”入口；手机位于相应首屏区域。顶层导航不新增清单栏目。 |
| 清单列表 | 标题“播客清单”；提供“导入清单”、标题搜索、单集数、已收录数、来源、作者和打开操作；仅一份清单时也正常呈现。 |
| 列表卡片 | 作者字段文案固定为“作者：”；源站入口文案固定为“小宇宙链接”，新标签打开真实原清单；“打开清单”进入站内详情。作者来自源清单作者字段，不能由内容推测。 |
| 列表删减 | 不保留副标题“沿着一份好清单，发现值得深入的一集。”、右侧策展说明区及步骤、底部理念说明或英文页脚；不显示“刚刚保存 · 演示状态”等虚构时间。 |
| 清单详情 | 保留原始顺序、逐集推荐语、Show Notes、节目和单集元数据、真实收录/队列状态；提供全部／未收录／已收录筛选、原文入口、刷新和删除。 |
| 导入弹窗 | 粘贴链接→预览内容→确认保存；支持取消、改链接、重复导入提示；主确认按钮在矮窗口和手机保持可达。提示导入不会批量入库或关注节目。 |
| Inbox 与详情 | 复用已有卡片及处理界面，补充来自某清单的来源与返回入口；不重新设计队列、笔记、转写、助手或加工面板。 |
| 播客列表及节目详情 | “我的订阅”调整为“我的播客”；支持全部／已关注／未关注筛选。未关注节目标明已收录数量，源站总数与本地数量分开；必要节目归属不等于已同步整档。 |
| 搜索与导入页 | 全局个人搜索只纳入已收录单集及必要节目记录，不添加清单候选搜索类型；原 OPML 导入和元数据同步保留，清单导入在清单页面。 |

- 风格沿用现有品牌、米色纸张、黑色分隔线、橙色强调和字体。原型底部切换、手机预览、重置工具不进入产品。
- 清单和条目拥有可直接访问的位置。浏览器刷新、前进后退保持所选对象；地址读取不能写库或触发加工。已入库单集复用实施时已存在的详情入口，不能把原型 hash 路由当作生产协议。
- 清单默认原始排序，过滤后保留原序号；不加入热度或个性化重排。推荐语独立于 Show Notes 和个人备注，缺失时不编造。
- 原清单创建时间、系统导入时间、最近成功获取时间是不同事实；需要展示时使用真实字段并明确含义，不将本地抓取时间写成源站更新时间。时间放详情或刷新反馈即可，不恢复已删除的列表演示说明。

### 3. 来源解析与导入

- 使用一个窄的小宇宙清单读取能力，解析目前支持的公开单集清单格式，输出确定性的清单元数据与条目；不使用 LLM 猜测成员或补推荐语。
- 先利用清单已返回的数据，必要时只补充用户选中单集的资料。读取 RSS 用于身份核对时，只采纳被选中的单集，不顺便写入其他条目。
- 清单预览在服务端绑定待提交版本，确认保存用户实际看过的版本；不信任客户端回传的任意身份结论、外部 HTML 或素材地址。预览过期时明确要求重新读取。
- 重复的源平台与清单 ID 定位已有清单，不新建、不隐式覆盖；刷新由用户独立触发。
- 能核实总数时显示总数，否则显示“已读取 N 集”。发现剩余分页、响应截断或缺失结构时不得声称完整导入；有明确不完整证据时阻止完整提交，说明已读取范围与失败原因。
- 本次样例读取成功不等于所有清单格式都受支持；首版限定已验证格式，其他格式明确拒绝。元数据可浏览与音频可播放、可加工分别判定。
- 复用项目 HTTP 与安全渲染机制；仅补此入口缺失的源站主机/路径校验、逐跳重定向检查、私网访问隔离和资源上限。付费、登录要求、403 和下架不绕过；来源内容不是 Agent 指令。

### 4. 数据及个人库复用

- 保存四类职责：清单本身、带顺序的清单条目、已采纳单集的外部身份映射、精简的采纳来源摘要。物理表名和适当合并是实施细节，唯一性与生命周期必须满足下述合同。
- 清单按源平台与外部清单 ID 唯一；清单内按外部单集身份去重；外部单集身份只能映射一个本地单集，并验证所属节目。
- 未采纳条目只保存发现元数据快照，可空关联本地单集。队列、个人备注、评分、Done 和知识产物只有既有本地单集这一份账本，不能复制到清单状态。
- 新节目仅提供已采纳单集的归属，持久化为未关注；已有节目保留原关注状态。须回读验证未关注值，不直接照搬会受默认值影响的旧创建路径。
- 无 RSS 的节目以真实“未知”表示 Feed，允许多个节目没有 Feed，同时保持非空 Feed 的唯一性；不伪造可访问 URL。迁移和接口输出需保持既有兼容。
- 增加最小单集级区分：清单新建、尚未被普通同步实际识别的单集，不进入工作流最近更新和报告候选；父节目已关注也一样。可用清单独有标识表达，旧单集维持原行为；普通同步真正识别同一集后才转换，单纯为去重解析 Feed 不转换。
- 以上单集仍可在个人搜索、节目详情、Inbox 和显式 Focus 使用。再次从清单采纳已有单集不改其同步时间或资格。普通同步时间继续遵守新增/实质更新规则。

### 5. 身份解析与采纳事务

- 首先复用已验证外部身份或原始单集链接，再核对所属节目、Feed 身份和 RSS 身份。不能简单将小宇宙 eid 当成 RSS GUID；也不能仅按标题、宽松日期或临时签名音频 URL 合并。
- 存在多个候选或冲突时暂停该条采纳，展示冲突及现有候选供明确选择；不扩展成通用全库合并工具。没有可靠证据时宁可不自动合并，也不能先制造重复集再盲合并。
- 后续 RSS 同步在创建前使用同一身份映射与既有严格识别能力。即使暂时无法取得 RSS GUID，也必须保证后续不会因来源键变化而创建重复集；命名空间外部键本身不是完整的去重方案。
- 网络读取在事务外完成；单集复用/创建、清单关联、外部映射、来源摘要及 Inbox 写入在同一数据库事务中完成。失败不得呈现完整成功；并发/重复提交复用既有结果，不重复入队。
- 在事务内检查当前队列状态，避免读取后另一页面移入 Focus 或 Done，采纳请求又将其改回 Inbox。保留已有跨节目冲突与软删除行为，不自动复活软删除内容。

### 6. 手动刷新和删除

- 刷新产生差异预览：新增、移出、排序和推荐语变化。确认后原子更新清单；同时校验旧修订，防止多个页面覆盖。无变化只记录实际检查结果。
- 新增条目保持未采纳；移出条目退出当前清单，但已收录单集及其个人状态、笔记、加工产物全部保留。失败或格式不完整保留上一份成功清单。
- 删除清单仅删除清单及未采纳资料，不删除个人单集、不取消关注。已采纳单集保留精简来源摘要，至少包含原清单身份、标题、URL 和采纳时间。
- 清单已删除时，来源仍可解释并打开原站，不能留下无提示的站内死链。无需保留无限清单版本历史。
- 个人库删除单集后，清单的本地关联解除；刷新不重新采纳，重新入库须独立明确动作。

### 7. 接口与交付切片

- 在现有认证下提供清单列表/详情、导入预览/确认、刷新预览/确认、单条采纳、删除能力。复用既有个人单集、行动队列和加工服务，不建立通用任务平台或平台插件体系。
- 按来源验证、清单浏览、原子采纳及同步隔离、手动刷新顺序实施。每一切片完成相应验收再向后推进；跨来源去重与同步隔离不是可省略的后续优化。
- 不将整个脏工作区作为实现基线成果交付，不顺带修改其他任务。数据库变更须隔离迁移演练；普通启动不自动迁移，生产变更另行授权。

## Testing Decisions

主验收边界是用户通过现有认证 API 和真实页面观察到的清单采纳流程；以“清单导入→只采纳一集→Inbox 回读→后续同步仍为同一集”为共同场景。优先沿用路由/Handler、真实隔离 SQLite、行动队列、Discovery 与 RSS 同步的现有测试入口。仅在外部小宇宙读取处替换成可控来源响应；必要时对解析器做小范围格式测试，不为每个内部函数建立新接口或重复校验。

好测试比较可见内容、数据库业务结果和外部副作用；不依赖内部调用次数、私有方法名、具体表拆分或与实现同构的断言。浏览器不以 Mock API 成功替代真实后端验收。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 真实样例解析 | 固定样例的 8 个不同单集身份、原始顺序和推荐语一致；现场读取可变数据时单独注明时间和差异。 |

真实浏览器至少覆盖桌面与 390px 手机，验证主链路、键盘、Esc/关闭焦点、搜索清空、长标题、全部条目、弹窗主按钮和原文链接。正常/慢请求/失败/首次访问的合同如下：

- 正常：展示实际清单，成功采纳后显示真实个人状态。
- 慢请求：已有清单保持可读，预览可取消，采纳只限制当前条目操作。
- 失败：保留上次成功清单及当前定位，显示具体原因与可用重试/原文入口。
- 首次访问：无清单显示导入入口；读取失败不冒充空清单，无历史结果不生成假的内容。

与现有发现页一起记录响应和有效内容时间，不能通过减少可用内容或拖延核心交互换取指标。完成相关检查及上述验收即可，不反复扩大无关测试。

## Out of Scope

- 节目型清单、自建清单、自动发现、定时刷新、清单订阅通知和个性化排序。
- 整份清单自动入库、自动关注节目、批量转写/加工、清单级报告或新增 AI 分析流程。
- 全网播客目录、通用抓取插件平台、全库身份回填或合并工具。
- 清单公开分享、账号关系同步、跨平台写回、付费或登录限制绕过。
- 独立播放中心、收听进度系统、重做既有 Inbox/Focus 工作台。
- 将原型的内存模拟、固定样例限制、模拟更新差异、底部工具条或简化首页当作生产实现。
- 本次 Spec 发布不执行产品编码、Git 提交/推送、生产部署、数据库迁移或真实数据写入。
