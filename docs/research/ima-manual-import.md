# ima 知识库人工导入与公开写入能力调研

日期：2026-08-24
对应：GitHub Issue #186
状态：只读一手来源调研完成；未执行真实账号导入验收。

| 问题 | 状态 | 结论 |

## 2. 检索范围与限制

本轮只读取公开页面、公开协议、腾讯云官方 SDK 产品清单和腾讯官方源码组织：

- 未执行登录、上传、写入或账号页面操作；
- 未读取或使用用户知识库、笔记、文件、Cookie、Token 或会话；
- 未抓取前端资源、猜测接口、调用私有 API 或分析客户端流量；
- 未访问 `robots.txt` 明确禁止自动抓取的 `/wiki` 等路径。[S2]

ima 的 `robots.txt` 声明了 `sitemap.xml`，但该地址在访问时返回 HTTP 404；同时 `/wiki` 被禁止抓取。因此本次公开帮助页发现范围不完整，这也是“未找到”不能升级为“不存在”的原因。[S2]

公开首页曾自动展示快捷登录框，本轮立即停止该页面路径；未执行登录、未进入账号页面，也未把其中任何账号信息作为证据。

## 3. 已证实的官方能力与操作

### 3.1 产品形态

**已证实：**

- ima 是以知识库为基础、提供“搜-读-写”体验的 AI 知识管家。[S1]
- 软件许可协议列出的主要能力包括 AI 搜索问答、网页浏览、在线笔记、知识库和 AI 助手。[S3]
- 官方服务形态包括 PC、APP、小程序和网页；协议也保留未来增加其他形态的可能，但没有据此公开 API 或 CLI。[S3]

### 3.2 可上传/提供的内容类别

**已证实：**

- 协议第 7.2.3 条明确列举用户上传/提供的知识库内容可包括：**文字、文档、图片、链接**。[S3]
- 用户必须拥有内容权利或充分授权；涉及个人信息时，应取得相应同意，或依法匿名化；内容还应真实、准确、客观并符合限定用途。[S3]

**未找到：**

- 文档扩展名白名单；
- Markdown、TXT、PDF、Word、JSON、HTML、EPUB 等逐项支持声明；
- 单文件/单库大小、页数、字符数、文件数量和频率上限；
- ZIP、目录、批量上传、增量更新或覆盖导入规则；
- 音频作为知识库附件的公开导入合同。

因此，#186 可把 `knowledge.md` 作为**待验收的主导入候选**，但 `metadata.json`、`manifest.json` 和 `IMPORT.md` 应先视为包内追溯/说明文件，不能默认宣称 ima 会解析或索引它们。

### 3.3 知识库相关操作

**已证实：**

- ima 知识库提供信息存储空间；用户可通过知识号公开发布知识库内容。[S3]
- 用户可修改已公开知识库的状态或删除知识库，以停止公开展示。[S3]
- 官方运营规则再次确认“上传、发布知识库”是受规则约束的用户操作；公开发布的知识库可被检索、展示、分享和用于 AI 问答。[S4]
- Skill 生态支持上传、发布及治理，但这不等于知识库写入 Skill 已公开或已满足自动化合同。[S4]

**未找到：**

- 同名文件重传是覆盖、追加、生成新版本还是重复；
- 私有知识库默认可见性与导入后发布状态；
- 导入完成回执、索引完成状态、失败码和重试语义；
- 可由机器稳定消费的幂等键或远端资源 ID。

## 4. 为什么人工导入包是当前合规 fallback

这里的“合规”指与公开产品协议和 #186 禁令一致的保守工程边界，不构成法律意见。

1. **服务侧动作走官方界面。** 官方协议明确预期用户上传/提供文字、文档、图片、链接；人工导入不需要调用未公开接口。[S3]
2. **不擅自扩张授权。** 协议说明未明示授权的权利由腾讯保留。没有公开写入合同时，不应把网页内部请求或客户端行为包装成 API。[S3]
3. **不保存账号能力。** MagicPodcast 只生成本地标准包，不持有 ima 凭据、Cookie、Token 或会话，也不自动登录。
4. **结果语义诚实。** 生成包只证明本地产物可交付，不证明远端已接收；状态必须保持 `manual_import` / `pending`，由人工验收后另行确认。
5. **可做内容审查。** 用户在上传前可以检查版权、个人信息、私有备注和来源；这与协议对授权、个人信息同意/匿名化和用途适配的要求一致。[S3]

启用自动 Adapter 的最低证据门槛是：腾讯公开、受支持且可长期引用的写入 API/CLI/Skill 文档，至少明确鉴权、授权范围、输入格式、幂等/重复行为、回执、错误码、配额、撤销和服务条款；随后另建或修订实施票并重新确认授权。

## 5. 真实账号人工验收清单

以下项目全部为**待验收**，只能由获批测试账号和测试知识库人工完成：

1. 官方当前界面是否提供“上传/导入”入口，入口位于哪个客户端和知识库层级。
2. `knowledge.md` 是否可选、可上传、可正确解析 UTF-8 中文、标题、列表、表格和来源链接。
3. `metadata.json`、`manifest.json`、`IMPORT.md` 是否可上传；若 JSON 不被接受，确认它们仅作为本地追溯文件，不要求导入。
4. 多文件是否支持一次选择；目录或 ZIP 是否被接受；当前文件大小、数量和频率限制。
5. 同一包重复导入时是去重、覆盖、版本化还是产生重复条目。
6. 导入后默认是否保持私有；任何发布到知识号/广场的动作是否需要单独确认。
7. 索引何时完成，能否基于逐字稿和纪要问答并返回可定位来源；失败时界面提供什么原因和恢复方式。
8. 删除、撤回公开状态和重新导入是否可逆，是否留下不可删除的副本。
9. 产品内是否存在官方“知识库写入 Skill”；若存在，人工核验其发布者、安装来源、权限提示、支持输入、回执、幂等、限流、撤销及服务条款，再决定是否另开自动 Adapter 票。

验收不得保存账号、Cookie、Token、二维码、会话或私人知识库内容；证据只保留脱敏后的产品版本、操作步骤、支持/拒绝结果和错误文案。
