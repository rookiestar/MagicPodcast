# 打开原节目页遇到站点拒绝时的站内恢复

状态：已实施（源码与测试为准；未当作生产发布完成）
日期：2026-08-27
跟踪：[GitHub #197](https://github.com/rookiestar/MagicPodcast/issues/197)
来源：节目详情打开小宇宙原页面间歇 403 的排查；产品倾向为「提示重试」并融合「小宇宙 App / 复制页面链接」备用打开方式

> 落地前须用源码与测试核对。冲突时以当时源码为准。

## Problem Statement

用户在节目详情打开原节目页时，浏览器新标签有时只看到小宇宙边缘返回的空 403 页。以 E196（物理 AI）为例，原始链接是 RSS 写入的 `https://www.xiaoyuzhoufm.com/episode/{id}?utm_source=rss`。同一条链接在同一出口下可以连续几次 200，下一次就是 OpenResty 的 `403 Forbidden` 空页。去掉 `utm_source=rss` 并不能消掉这个拒绝。

MagicPodcast 并没有把链接改坏：Inbox「打开原节目」、播客详情标题、Discovery「打开节目页面」、首页报告「打开原单集」都是把已消毒的 `episode.Link` / `original_url` 交给浏览器直连。用户无法从空白 403 页判断是链接失效、节目付费还是站点拒绝，也没有回到 MagicPodcast 后可继续用的打开方式。

跨源限制下，MagicPodcast **读不到**已经打开的小宇宙标签页，因此不能在对方页面上检测 403。若不在站内留下恢复入口，用户只能反复盲点原链接。

## Solution

把「打开原节目」从一次性外跳，改成：**先照常打开网页，同时在 MagicPodcast 留下可见的 403 恢复区**。恢复区只对小宇宙网页单集链接出现，明确写清「如果新页面是 403」：

1. **重试打开**：再开一次规范化后的网页单集地址。
2. **用小宇宙打开**：打开小宇宙官方网页已经在使用的 `cosmos://page.cos/episode/{id}` 深链。
3. **复制页面链接**：复制不含跟踪参数的 `https://www.xiaoyuzhoufm.com/episode/{id}`。

非小宇宙链接保持现在的直接打开，不出现恢复区。不向小宇宙再发探测请求，不代理其网页，不改数据库里存的 RSS 链接，也不把外跳当成 Done。

## User Stories

1. 作为 Inbox 用户，我希望点击「打开原节目」后仍立即尝试打开原网页，以便成功时不必多点一步。
2. 作为 Inbox 用户，我希望打开小宇宙单集页后看到站内恢复说明，以便新标签如果是 403 时知道该怎么办。
3. 作为 Inbox 用户，我希望恢复说明写明「如果新页面是 403」，以便不会把正常打开误当成失败。
4. 作为刚从 403 标签回到 MagicPodcast 的用户，我希望恢复区还在，以便不必重新寻找打开入口。
5. 作为遇到 403 的用户，我希望可以重试打开网页，以便赶上小宇宙边缘下一次放行。
6. 作为遇到 403 的用户，我希望重试使用去掉跟踪参数的网页地址，以便少带 RSS 来源标记。
7. 作为遇到 403 的用户，我希望可以用小宇宙 App 打开同一集，以便绕过网页边缘拒绝。
8. 作为遇到 403 的用户，我希望可以复制不含跟踪参数的页面链接，以便粘贴到另一个浏览器或发给自己。
9. 作为没有安装小宇宙 App 的用户，我希望复制和重试仍然可用，以便 App 深链失败时不是死路。
10. 作为打开非小宇宙原节目的用户，我希望行为与现在相同、不出现 403 恢复区，以便不被无关提示打扰。
11. 作为原节目链接不可安全打开的用户，我希望继续看到「不可安全打开」，以便危险协议不会借恢复区绕过消毒。
12. 作为 Inbox 用户，我希望第一次成功点击「打开原节目」仍只记录进行中，以便外跳不等于完成。
13. 作为 Inbox 用户，我希望重试、用小宇宙打开或复制链接都不会自动 Done，以便完成仍需我确认。
14. 作为 Inbox 用户，我希望重试不会重复制造新的队列状态，以便进行中记录保持一次意图。
15. 作为进行中记录保存失败的用户，我希望原有的「已打开但未保存」提示与 403 恢复可以同时理解，以便两种失败不会互相覆盖到无法操作。
16. 作为播客详情页用户，我希望点击单集标题打开小宇宙页面后也能使用同一套恢复，以便不必先收集到 Inbox。
17. 作为移动播客详情用户，我希望「查看详情」打开小宇宙单集后也能恢复，以便手机上遇到 403 同样有出路。
18. 作为 Discovery 用户，我希望「打开节目页面」在小宇宙单集上提供同一套恢复，以便发现流程与消费流程一致。
19. 作为首页报告读者，我希望「打开原单集」在小宇宙单集上提供同一套恢复，以便从报告跳转时也不至于卡在 403。
20. 作为打开小宇宙播客首页、用户页或其他非单集页的用户，我希望不套用单集恢复，以便深链和复制文案不会指错对象。
21. 作为 `web.xiaoyuzhoufm.com` 单集链接的用户，我希望同样被识别为小宇宙单集，以便旧网页域名也能恢复。
22. 作为带 `utm_source=rss` 的 RSS 链接用户，我希望第一次仍打开库里那条已消毒链接，以便不改变当前成功路径。
23. 作为复制链接的用户，我希望剪贴板里是规范网页地址而不是 RSS 带参地址，以便分享和再次打开更干净。
24. 作为键盘用户，我希望可以只用键盘完成打开、重试、复制、用小宇宙打开和关闭恢复区，以便不依赖鼠标。
25. 作为读屏用户，我希望恢复说明和三个动作都有文字名称，以便不把 403 恢复理解成装饰。
26. 作为触屏用户，我希望恢复动作热区不小于 44×44 CSS 像素，以便单手可点。
27. 作为想关掉提示的用户，我希望可以关闭恢复区，以便成功打开后不必一直看到 403 说明。
28. 作为再次打开另一集的用户，我希望恢复区换成当前这一集，以便不会对错误的单集重试或复制。
29. 作为剪贴板被拒绝的用户，我希望看到复制失败而不是假装已复制，以便改用重试或 App。
30. 作为操作系统打不开 `cosmos://` 的用户，我希望网页重试和复制仍在，以便 App 动作失败不是唯一出口。
31. 作为维护者，我希望所有打开原节目的界面共用同一套识别与恢复规则，以便不会只修 Inbox、漏掉详情和报告。
32. 作为维护者，我希望不向小宇宙增加探测、代理或抓取请求，以便恢复能力不会加重已有的边缘拒绝。
33. 作为维护者，我希望不改 RSS 抓取、Feed 403 策略或数据库里的 `episode.Link`，以便这次只处理打开原页面的体验。
34. 作为单人自托管用户，我希望恢复逻辑只在前端根据已有链接派生，以便不新增 API、schema 或生产出口实验。
35. 作为安全敏感用户，我希望 `cosmos://` 只来自已经识别出的小宇宙单集 ID，以便用户输入或 Show Notes 里的任意深链不会被放行。
36. 作为慢网络用户，我希望打开原网页不被恢复区拖住，以便提示出现之前新标签已经开始加载。
37. 作为首次访问用户，我希望没有打开过原节目时不预先展示 403 恢复，以便空态更干净。
38. 作为同时打开多个窗口的用户，我希望恢复区属于当前节目详情上下文，以便不会把 A 集的恢复动作用到 B 集。

## Implementation Decisions

- **检测边界**：不读取、不嵌入、不代理小宇宙页面。403 是对方源上的间歇拒绝，站内无法可靠观测。产品上的「识别」是：对小宇宙**网页单集**链接，在用户发起打开之后展示有条件恢复，而不是根据一次服务端探测结果拦截或改写导航。
- **不探测**：禁止为这次恢复新增对 `www.xiaoyuzhoufm.com`、`web.xiaoyuzhoufm.com`、`feed.xyzfm.space` 或小宇宙 API 的预检、HEAD、健康检查或重试抓取。现有 Feed 403 策略与这次体验问题分开。
- **唯一 seam**：新增一个前端纯模块，输入已消毒的原节目 URL，输出要不要提供恢复、第一次打开用的 URL、重试 URL、App URL、复制文本。所有界面只消费这份结果，不各自解析小宇宙域名或手写深链。
- **识别规则**：仅当消毒后的 http(s) URL 主机是 `www.xiaoyuzhoufm.com` 或 `web.xiaoyuzhoufm.com`，且路径是 `/episode/{id}` 时提供恢复。`id` 取路径第一段，去掉查询和片段。其他路径（播客页、用户页、评论页）不提供单集恢复。
- **第一次打开**：继续打开调用方传入的已消毒原 URL（通常仍带 `utm_source=rss`）。不把首次导航改成规范地址，以免改变当前多数时候 200 的路径。
- **重试打开**：打开规范网页地址 `https://www.xiaoyuzhoufm.com/episode/{id}`，去掉查询。这与现有报告二维码使用的网页形态一致。
- **复制文本**：与重试相同的规范网页地址。
- **App 打开**：仅从已识别的单集 ID 派生 `cosmos://page.cos/episode/{id}`。该 scheme 已出现在小宇宙官方网页的播客/用户/评论链上，本期把它当作小宇宙第一方深链，而不是新的第三方应用连接器。这是对 Inbox 规格「本期只使用已有原始节目链接、不上未验证深链」的**收窄例外**：只允许这一条由模块派生的单集深链。
- **消毒关系**：继续先走现有内容 URL 消毒（只允许安全 http(s) 等）。`cosmos://` **不得**通过放宽通用消毒函数进入任意 `href`。App 按钮只绑定模块派生的那一条深链。
- **调用面**：Inbox 节目详情、播客库单集标题与移动端「查看详情」、Discovery「打开节目页面」、首页报告「打开原单集」。这四处凡是打开单集原页面的动作，都要接到同一模块和同一恢复文案结构。
- **恢复区生命周期**：用户对当前单集发起打开后出现，关闭前保持；换一集则替换为新集；关闭后到下一次打开前不再显示。不使用会自动消失的纯 toast 作为唯一恢复面。
- **Inbox 进行中**：只在用户第一次点「打开原节目」时按现有逻辑记录进行中；恢复区的三个动作不再触发队列迁移或第二次「当作新的外跳意图」。进行中保存失败的现有提示保留。
- **非小宇宙或无法识别 ID**：不展示恢复区；行为保持为当前的直接 `window.open` / `a[href]`。
- **无 schema / API / 迁移**：不改 `episodes.link`，不改 RSS 解析，不改图片代理白名单，不改后端 Feed 客户端。
- **无新 ADR**：这是前端打开原节目的体验修补，不改变发现/消费队列或知识桥接决策。领域词「原节目页恢复」只在本 Spec 使用；未落地前不写入领域词汇表。

模块对外结果的决策形状（不是实现草稿，只锁定字段含义）：

```ts
type OriginalEpisodeOpenPlan = {
  recovery: false;
  openUrl: string; // 已消毒，调用方照常打开
} | {
  recovery: true;
  openUrl: string;   // 首次打开：已消毒的原 URL
  retryUrl: string;  // https://www.xiaoyuzhoufm.com/episode/{id}
  appUrl: string;    // cosmos://page.cos/episode/{id}
  copyText: string;  // 与 retryUrl 相同
}
```

## Testing Decisions

- 测外部行为，不测按钮内部有没有某个 class、也不测是否「调用了 window.open 的第几个参数拼法」除非它属于产品契约（新标签、noopener）。
- **主测试面就是上述纯模块**：给定 URL，断言是否恢复、三条文案/地址是否正确。覆盖带 `utm_source=rss` 的 www 单集、web 子域、非单集路径、非小宇宙、javascript/data、缺 ID、多余路径段。
- **界面测试只锁调用面契约**：Inbox 打开小宇宙单集后出现恢复说明和三个动作；重试打开规范地址；App 打开派生深链；复制写入规范地址；非小宇宙不出现恢复；危险链接仍不可打开；第一次打开仍记录进行中且恢复动作不 Done。
- 先验：Inbox 详情「打开原节目仍外跳、失败也只标进行中」的测试；内容 URL 消毒测试；首页报告危险链接被剥掉的测试。新测试应延续这些入口，而不是另起一套打开语义。
- 不把「向小宇宙打真实 HTTP 看是不是 403」写进仓库测试。间歇 403 是上游事实，本票只保证恢复入口在打开之后可用。
- 不新增后端测试，除非误改了链接消毒或报告链接过滤；那应被视为 scope 泄漏。

## Out of Scope

- Feed 抓取、`feed.xyzfm.space` 403、熔断、软限速、固定出口或 UA 实验。
- 服务端预检原页面、反向代理小宇宙 HTML、iframe 嵌入。
- 改写或回填数据库中的 `episode.Link` / `original_url`。
- 把任意 `cosmos://`、通用应用连接器或未识别的第三方深链加入内容消毒白名单。
- 邮件报告、二维码、播放音频按钮、图片代理 403。
- 自动把 403 当成节目下架、付费集或链接损坏。
- 生产环境对照实验、换出口、部署或真实数据库写。

## Further Notes

- 一手复现：对 E196 原 URL，浏览器 UA 连续请求可在数次内打出 OpenResty 空 403 页；并发下 403 比例更高。规范 URL 同样会 403，因此恢复必须包含重试，而不能只靠去参数。
- 小宇宙官方网页在未登录时对 `get-me` 返回 401，页面仍能渲染。401 不是这次用户看到的空 403 页，恢复文案不要写成「请登录」。
- 若后续证实 `cosmos://page.cos/episode/{id}` 在目标系统上无效，应先改模块里的 App URL 派生，而不是让各界面分叉；复制与重试仍是有效兜底。
- 实施时若恢复区文案、动作名或 Inbox 进行中语义需要和现有通知并列，以「用户仍能完成重试 / App / 复制」为验收，而不是以少一条提示为验收。
