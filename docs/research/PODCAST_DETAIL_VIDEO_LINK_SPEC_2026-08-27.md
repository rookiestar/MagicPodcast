# 播客详情页附上视频链接

状态：已实施（源码与测试为准；生产库 schema 24 仍须人审 `--apply`，未当作生产发布完成）
日期：2026-08-27
跟踪：[GitHub #199](https://github.com/rookiestar/MagicPodcast/issues/199)
依据：[小宇宙视频单集 URL 研究](XIAOYUZHOU_VIDEO_EPISODE_URL_2026-08-27.md)；产品要求在播客详情页单集上附上视频链接

> 落地前须用源码与测试核对。真实数据库迁移 `--apply` 需单独人审授权。

## Problem Statement

小宇宙已经有视频播客。同一集在网页上有「播放视频」，RSS 却仍然只给音频 enclosure。MagicPodcast 同步把这条音频写进 `medium_url`，播客详情里的播放按钮打开的是声音文件，标题才打开节目页。用户无法从详情卡片看出「这集能看视频」，也没有一条与播放音频并列的视频入口。

视频文件本身是带签名、会过期的 HLS preview，不能当第二份 enclosure 存进库。若不加区分地把所有小宇宙单集都标成视频，音频集也会被骗点；若在打开详情时现查小宇宙，又会拖慢首屏并加重边缘拒绝。

## Solution

在播客详情的单集卡片上，**只有已确认有视频的单集**多一个「看视频」动作。它打开的是**稳定节目页**（与现有原节目链接相同），不是过期 m3u8。现有「播放」继续只打开音频。

是否有视频用三态记在单集上：`unknown` / `unavailable` / `available`。只在既有 Feed 同步里、对能解析出小宇宙单集 ID 的条目，按共享限速去读小宇宙**已经公开的**单集页或 `video-playback` 的有/无，写入三态。详情列表加载不额外访问小宇宙。签名 HLS 永不入库、不出现在 API、不当成播放按钮目标。

## User Stories

1. 作为播客详情读者，我希望视频单集上有「看视频」，以便和听音频分开。
2. 作为播客详情读者，我希望点「看视频」打开小宇宙节目页，以便用对方自己的播放器看。
3. 作为播客详情读者，我希望点「播放」仍然打开音频文件，以便通勤或后台听。
4. 作为播客详情读者，我希望没有视频的单集不出现「看视频」，以便不被误导。
5. 作为尚未判定的单集读者，我希望先不显示「看视频」，以便未知不等于可看。
6. 作为只有视频没有音频 enclosure 的单集读者，我希望仍能看到「看视频」，以便不是非有音频不可。
7. 作为没有安全节目页链接的读者，我希望即使标记为有视频也不出现外跳按钮，以便危险协议不会借视频入口绕过消毒。
8. 作为标题已经可点的读者，我希望「看视频」仍单独存在，以便不必把标题语义理解成看视频。
9. 作为使用 #197 恢复的用户，我希望从「看视频」打开小宇宙页后同样可以使用 403 恢复，以便边缘拒绝时有重试和复制。
10. 作为移动详情用户，我希望「看视频」热区不小于 44×44 CSS 像素，以便单手可点。
11. 作为键盘用户，我希望可以 Tab 到「看视频」并回车打开，以便不依赖鼠标。
12. 作为读屏用户，我希望按钮名称是「看视频」而不是只靠图标，以便和「播放」区分。
13. 作为首次打开播客详情的用户，我希望单集列表仍按现有速度出现，以便视频能力不拖住首屏。
14. 作为慢网络用户，我希望详情请求不因查询小宇宙视频而变慢，以便有效内容出现时间不变。
15. 作为请求失败用户，我希望列表仍显示标题、音频播放和原链接，以便视频标记缺失不等于整卡不可用。
16. 作为非小宇宙节目的读者，我希望卡片完全不变，以便其他源不受影响。
17. 作为小宇宙纯音频集的读者，我希望没有「看视频」，以便和视频集区分。
18. 作为最新一集是视频的节目读者，我希望详情头部的「播放最新一集」仍打开音频 enclosure，以便不把最新音频入口改成视频。
19. 作为同步维护者，我希望判定失败时保持 `unknown` 而不是写成无视频，以便下次同步还能再试。
20. 作为同步维护者，我希望已判定的单集在内容未变时不要每批都重打小宇宙，以便不加重 403。
21. 作为 Feed 韧性维护者，我希望视频探测走小宇宙共享限速，以便不另开一条打爆边缘的队列。
22. 作为合规使用者，我希望不登录、不带 cookie、不打未公开 App 接口，以便停留在网页已用的公开读接口。
23. 作为数据维护者，我希望库里没有 HLS、auth_key 或过期时间，以便过期签名不会污染 `medium_url`。
24. 作为 API 使用者，我希望单集列表带上视频三态，以便详情页不必二次猜测。
25. 作为 Fixture 开发者，我希望测试数据能构造有视频 / 无视频 / 未知三种卡片，以便不依赖外网。
26. 作为 Inbox 用户，我希望本期不必改消费队列语义，以便视频入口不自动记进行中。
27. 作为 Discovery / 报告读者，我希望本期不必先改那些表面，以便范围收在播客详情。
28. 作为加工流水线维护者，我希望转写仍用音频 enclosure，以便视频预览片源不进入现有加工。
29. 作为封面加载用户，我希望即使将来用视频封面，也只走已允许的图片域名，以便不把 `video.xyzcdn.net` 塞进图片代理。
30. 作为触屏用户，我希望「播放」和「看视频」并排且互不遮挡，以便不会点错。
31. 作为只想打开原节目的用户，我希望点标题的行为不变，以便视频按钮是增量。
32. 作为迁移操作者，我希望 apply 前有备份和确认，以便三态列不会在未授权时写入生产库。
33. 作为回退操作者，我希望去掉「看视频」后音频播放与原链接仍可用，以便视频能力可逆。
34. 作为未知随后变为有视频的单集读者，我希望下次成功同步后卡片出现「看视频」，以便判定可以前进。
35. 作为曾经有视频后来 404 的单集读者，我希望下次成功探测后按钮消失，以便过期下架能反映出来。

## Implementation Decisions

- **「视频链接」的产品含义**：稳定节目页，不是 HLS。卡片上的 `href` 使用已消毒的 `episode.link`（与 #197 原节目打开同一套计划里的 `openUrl`）。
- **「播放」不变**：继续只打开 `medium_url`。禁止把签名 m3u8 写入或覆盖 `medium_url`、`newest_enclosure_url`。
- **三态，不用布尔**：`unknown`（缺省）、`unavailable`、`available`。未知不展示「看视频」。
- **Schema**：单集表增加有界字符串列保存三态（空或 `unknown` 视为未知）。不增加视频文件 URL 列、不增加 expiresAt。迁移需登记人审，经 `cmd/migrate` 显式 apply；普通启动只读校验。
- **API**：播客详情使用的单集列表响应增加 `video_availability`。其它列表若共用同一响应函数则自然带上，但本期 UI 只改播客详情单集卡。
- **判定来源**：仅当节目页链接能解析出小宇宙单集 ID。读取公开单集 JSON 的 `video.available`，或 `GET .../api/episodes/{eid}/video-playback` 的 200/404。404 → `unavailable`；`available: true` 或 playback 200 → `available`。解析失败、超时、403/5xx → 保持 `unknown`。
- **何时探测**：挂在既有 Feed/单集同步成功路径上，只处理本批新建或内容变化的小宇宙单集，且已是 `unknown` 或需要在内容变化后复核。已是终态且 GUID/链接未变则跳过。每节目每批有上限，超出留待后续批次，避免一次打满历史集。
- **限速**：使用小宇宙已有共享单队列 / 软限速，不新开并发池，不在详情 GET 时探测。
- **详情页加载**：只读库里的三态，零额外上游请求。正常 / 慢 / 失败 / 首次访问的用户可见列表内容与现在一致，只是部分卡片多一个按钮。
- **UI**：播客详情 `EpisodeCard` 在「播放」旁增加「看视频」。展示条件：三态为 `available` 且存在安全节目页 URL。沿用 44px 热区和 #197 打开后的恢复区。
- **头部「播放最新一集」**：本期不改，仍用最新音频 enclosure。
- **图片**：若要用视频封面，只允许已在封面白名单中的 `image.xyzcdn.net`；本期可以只用现有 `image_url`，不强制新列。
- **Inbox 进行中**：从详情「看视频」外跳**不**记消费进行中（那是 Inbox「打开原节目」的契约）。
- **模块 seam**：一个纯函数，输入消毒后的节目页 URL 与三态，输出是否显示以及打开地址。探测结果解析是第二个纯函数（JSON / HTTP 状态 → 三态）。同步与 UI 都只消费这两个结果。
- **法律与探测边界**：不登录、不带 Cookie、不打 App 私有接口、不下载视频分片。403 记入既有失败分类，不当成「无视频」。

三态与动作的决策形状：

```ts
type VideoAvailability = "unknown" | "unavailable" | "available";

type EpisodeVideoAction =
  | { show: false }
  | { show: true; href: string };
```

## Testing Decisions

- 测外部行为：有没有「看视频」、点了打开哪类 URL、音频播放是否仍指向 enclosure。
- **主测试面 1**：纯函数——`available` + 安全小宇宙链接 → show；`unknown`/`unavailable` → 不 show；危险链接 → 不 show。
- **主测试面 2**：探测解析——公开 JSON `video.available=true/false`、playback 200/404、403/超时保持 unknown。用固定夹具，不打真小宇宙。
- **界面**：播客详情单集卡在 `available` 时出现「看视频」；点开使用节目页而不是 m3u8；`medium_url` 播放不变。先验：`EpisodeCard` 播放按钮与 #197 恢复测试。
- **同步**：httptest 模拟公开页/playback，断言只写三态、库中无 `auth_key` / `m3u8`。
- 不把「真去拉 HLS 分片」写进仓库测试。

## Out of Scope

- 站内嵌 HLS 播放器、拉 720 全片、登录小宇宙。
- 把视频当转写/加工输入。
- 改 Inbox / Discovery / 首页报告的主按钮（字段可顺带出现在共用响应里，UI 不在本期）。
- 改「播放最新一集」为视频。
- 把 `video.xyzcdn.net` 加入图片代理。
- Feed 主 URL、熔断策略、生产 migrate apply、部署。

## Further Notes

- 一手依据见视频 URL 研究：RSS 无视频；节目页稳定；`video-playback` 返回 `/hls/preview/` 与约 4 小时 TTL。
- 打开 m3u8 新标签体验差，故产品链接坚持节目页。
- 生产库加列必须按迁移指南备份后 apply；Fixture 需带三种三态样例。
- 实施前把「单集视频三态列」写入人审队列，未经授权不得对真实库 `--apply`。
