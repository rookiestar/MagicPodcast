# 首页往期报告按工作流筛选方案

状态：已实施（PR #146，2026-08-21 合入 main；实现见 `frontend/src/lib/homepageReportWorkflowFilter.ts` 与 `WorkflowReportWorkbench.tsx`）
日期：2026-08-21

## 1. 背景与目标

首页“精选报告”的往期抽屉目前按日期展示最近 30 份工作流报告。随着所有工作流报告都具备首页候选资格，同一天和跨日期的报告数量会增加，用户需要更快定位某个工作流持续产出的报告。

本方案只为往期报告增加“按工作流筛选”，不搜索报告正文、单集或其他字段，也不改变首页报告资格、排序、加载范围和阅读方式。

成功标准：

1. 用户能在往期抽屉中按一个或多个工作流筛选报告。
2. 工作流改名不会把同一工作流拆成多个筛选项。
3. 用户能理解筛选只覆盖当前加载的最近 30 份报告。
4. 筛选不会触发额外 API 请求，也不会影响首页报告正文按需加载。
5. 桌面、390px 移动端和键盘操作均可完成筛选、清除和关闭抽屉。

## 2. 产品行为

### 2.1 展示范围

- 筛选仅作用于“往期报告”抽屉。
- 继续保留现有日期分组；筛选后隐藏没有匹配报告的日期组。
- 数据范围保持为现有最近 30 份报告元数据。
- 筛选不影响今日报告、最新往期 Banner、最近更新或 Inbox。
- 当最近 30 份报告只来自一个工作流时，不显示筛选入口。

### 2.2 工作流选项

- 以稳定的 `workflow_id` 作为筛选身份。
- 从当前最近 30 份报告元数据中聚合工作流选项。
- 同一 `workflow_id` 即使名称发生变化，也只显示一个选项。
- 选项主名称使用该工作流最近一份报告中的 `workflow_name`。
- 关键词匹配该工作流在当前 30 份报告中出现过的所有名称，确保改名前后均可找到。
- 选项按最近一份报告的完成时间倒序排列。
- 每个选项显示其在当前 30 份报告中的报告数量。

### 2.3 筛选交互

- 工作流支持多选，多个工作流之间使用 OR 语义。
- 勾选或取消勾选后立即更新往期报告列表，不需要“应用”按钮。
- 关键词只过滤工作流选项，不直接过滤报告。
- 筛选面板默认折叠，可由用户展开。
- 界面明确提示“筛选最近 30 份”。
- 面板折叠后，如存在选择，入口显示已选工作流数量，并提供直接清除按钮。
- 关键词没有匹配选项时，显示工作流选项空态，不改变已选工作流。
- 报告筛选结果为空时，保留当前选择，显示无结果说明和一键清除筛选入口。

### 2.4 状态生命周期

- 同一次页面访问中，关闭并重新打开往期抽屉后保留已选工作流。
- 关闭抽屉时折叠筛选面板并清空关键词。
- 刷新页面后重置全部筛选状态。
- 报告数据刷新时，自动移除当前数据中已不存在的 `workflow_id` 选择。
- 数据刷新后仍存在的选择继续生效。

## 3. 实现边界

### 3.1 数据与接口

- 纯前端实现，复用现有报告元数据中的 `workflow_id`、`workflow_name` 和 `completed_at`。
- 不增加或修改 API、数据库 schema、迁移、工作流配置或报告生成逻辑。
- 不扩大 `history_limit=30`，不预取报告正文。
- 报告详情继续在用户选择具体往期报告后按需加载。

### 3.2 前端结构

- 在现有往期抽屉中增加工作流筛选区，筛选结果继续交给现有日期分组和报告选择流程。
- 将选项聚合、名称兼容、排序和报告过滤提炼为可独立测试的纯逻辑。
- 筛选面板沿用现有抽屉、按钮、复选框、空态和焦点样式，不引入新的视觉系统。
- 新增内部筛选选项模型即可，不新增公共接口；模型至少表达稳定工作流 ID、当前显示名、历史名称集合、最近完成时间和当前范围内报告数。

### 3.3 领域语言与决策记录

- “往期报告”指首页精选报告抽屉中当前加载的历史工作流报告集合。
- 后续实施时在项目领域词汇表中补充“往期报告”，避免与工作流详情页的“执行历史”混用。
- 本功能是可逆的前端交互决策，不新增 ADR。

## 4. 测试与验收

### 4.1 用户可见行为

以 `WorkflowReportWorkbench` 的用户可见行为测试为主要 seam：

1. 少于两个工作流时不显示筛选入口。
2. 两个及以上工作流时显示筛选入口和“筛选最近 30 份”提示。
3. 单选只保留对应工作流报告，并保持日期分组。
4. 多选使用 OR 语义。
5. 取消和清除后恢复完整 30 份范围。
6. 折叠状态显示已选数量，并可直接清除。
7. 关键词只改变工作流选项，不直接改变报告结果。
8. 关键词能匹配同一工作流的历史名称，选项仍显示最近名称。
9. 报告无结果时保留选择并提供清除入口。
10. 关闭抽屉后保留选择、折叠面板并清空关键词。
11. 页面刷新后筛选重置。
12. 数据刷新时移除已不存在的选择，保留仍有效选择。
13. 选择筛选后的报告仍按现有流程加载正文并关闭抽屉。
14. Escape、关闭按钮和焦点恢复行为不回归。

### 4.2 纯逻辑

- 按 `workflow_id` 聚合选项。
- 同一 ID 的多名称归一与历史名称搜索。
- 最近名称选择、最近产出排序和报告计数。
- 单选、多选 OR、空选择和不存在选择的过滤结果。
- 无效或空关键词的归一行为。

### 4.3 双端与质量检查

- 桌面抽屉检查展开、折叠、长选项列表、无结果和清除。
- 390px 移动端检查不横向溢出、触摸目标、抽屉滚动和筛选面板占用。
- 键盘检查 Tab 顺序、复选框、清除按钮、Escape 和关闭后的焦点恢复。
- 实施完成后运行前端定向测试、全量测试、类型检查、lint、生产构建、Markdown 链接检查及 `git diff --check`。

- 服务端筛选、分页或增加历史报告数量。
- 保存到 URL、本地存储、账号偏好或跨页面持久化。
- 修改报告排序、日期分组、详情加载、首页候选资格或报告周期识别。
- 新增报告详情页、归档页、统计看板或批量操作。
