# #346 逐字稿人物与发言验收

对应 [Spec #346](https://github.com/rookiestar/MagicPodcast/issues/346)。实现基于 `f3ccceabb74985517d169fca5be46c324477dbbe`，分支 `codex/issue-346-transcript-people`。

## 交付边界

- 人物识别与审阅迁入逐字稿；识别只生成服务端草稿，明确应用才更新发言归属和人物检索。
- 草稿、人工审阅修改和已应用结果使用 SQLite 持久保存。原文、Speaker 标签、时间戳保持不变，姓名通过已确认归属呈现。
- 新增 Schema 30 的人物草稿记录。复用现有人物、纠正、来源与修订机制；不建立第二套人物索引或通用审核系统。
- 用户确认和索引更新在同一事务完成。旧版本提交、重复请求、并发编辑及索引写入失败均有行为验证。
- 草稿更新不打断使用既有发言的回答；实际发言归属变化会拒绝将进行中的旧回答标记为完成。
- 快照脱敏规则升级至 v12：草稿中的原文、证据、人工修改和应用请求随其他人物私有记录一并移除；对应迁移和脱敏测试通过。
- 本记录为本地隔离验收；没有修改主工作区、真实数据库、妙记或生产服务。

## 验收标准映射

| 标准 | 证据与结果 |
| --- | --- |
| AC1 入口独立 | 逐字稿工具栏与审阅面板完成识别和编辑；Copilot 仅保留“到逐字稿确认人物”。组件测试及普通浏览器路径验证。 |
| AC2 明确匹配范围 | 按原 Speaker 展示建议、角色、证据、全部或局部片段。证据与片段校验沿用既有真实 Runtime 合同；同名人物、例外片段及不确定结果保守保留。 |
| AC3 未确认不生效 | `TestReviewDraftPersistsWithoutPublishingThenAppliesSelectedMatches` 及浏览器保存前后检查：保存草稿后姓名未变化；人物检索只认可人工确认记录。 |
| AC4 草稿持久化 | `TestReviewSurvivesDatabaseCloseAndReopen` 真实关闭并重开 SQLite；浏览器刷新后恢复修改后的草稿姓名。失败和未保存提示有界面测试。 |
| AC5 部分确认 | 选择集合在事务内应用，未选项目与其他已确认发言保持；重叠片段选择被拒绝。服务测试覆盖部分确认与冲突。 |
| AC6 不覆盖人工决定 | 新识别保存独立记录；已应用事实保持。迟到请求、取消和失败有生命周期测试；保存旧草稿不会静默覆盖较新提交。 |
| AC7 原位编辑 | 双击及编辑按钮、整组或单段、空姓名、失焦和 Esc、无预先识别的手动命名均有组件/服务测试。手机窄屏编辑与焦点循环实际操作通过。 |
| AC8 同步纠正 | 浏览器将同一 Speaker 的单段改为另一人物，其余三段保留原名；解除后恢复原 Speaker。新增旧别名回归防止确认新姓名后仍解析回旧姓名。 |
| AC9 人物问答 | 普通浏览器中确认姓名后 @张老师；真实 Codex Runtime 返回带引用的模拟回答。已核对引用 S3 对应当前已确认人物的片段 6，内容支持回答；未采用未知 Speaker 的观点。 |
| AC10 失效与历史 | 人物变更事件刷新选择，失效时保留问题且不按同名重绑。`TestPersonaAnswerRejectsChangedFactsButNotSavedDrafts` 区分实际归属变化与草稿更新；历史对话不被改写。 |
| AC11 并发与原子性 | `TestConcurrentReviewCannotOverwriteAnotherApproval`：不同确认竞争时一个成功、一个过期；相同请求重试不重复建人物。真实 SQLite 索引失败注入证明事实与索引一起回滚。 |
| AC12 来源变化 | 新版逐字稿不继承旧标签绑定；旧记录保留，当前读取与人物检索排除旧来源。来源变化、同源人工保护及旧索引拒绝测试通过。 |
| AC13 历史记录 | Schema 迁移不伪造用户确认；历史自动事实不能成为当前人物观点。旧名字与对应片段的明确人工确认继续按来源有效性使用。 |
| AC14 界面与播放 | 1200px 桌面、390px 窄屏人工看图；无页面横向溢出，窄屏完整面板与编辑弹层可操作。编辑不请求或播放音频；原有播放、定位和跟随测试保留。 |
| AC15 四种状态 | 见下方时序与内容可用性记录。识别和人物读取失败不清空逐字稿或既有归属。 |

## 自动化与实际执行证据

本地检查：

- 后端 `go test ./...`、`go vet ./...`。
- 人物及单集助手 `go test -race`，覆盖草稿持久化、确认、纠正、并发和回答期间的事实变化。
- 前端全部 956 项测试；最终焦点与历史状态调整再定向通过 5 项人物界面测试。TypeScript、ESLint 与生产构建均通过；构建生成的配置差异已恢复并再次通过类型检查。
- 开始时旧用例假定识别立即生效，已改为显式批准的 fixture 或新的草稿断言；没有恢复自动批准的生产旁路。
- UI 全量检查曾遇到无关字体加载计时用例在高并发下失败；单独复核及限制为两个测试 worker 的全量检查通过，未放宽其断言或产品逻辑。

真实识别使用两集既有原始导出，重新调用 Runtime，未重放旧模型结果：

| 材料 | 新运行观察 | 解释 |
| --- | --- | --- |
| 66314，双人访谈 | 张小珺 249 段、曾鸣 288 段；37 段仍待归属；约 120 秒 | 名字及发言范围来自新的识别结果；未把未归属片段算作人物观点。 |
| 66224，多说话人 | 曲凯无可靠发言绑定；逯雨鑫 63 段、陈皮 2 段；48 段待归属；约 57 秒 | 有人物身份并不意味着拥有全部 Speaker 发言；无有效发言者不能用于模拟回答。 |

上述计数是代表性样本观察，不是全库准确率。识别测试中的程序化批准仅验证隔离服务链；用户确认交互另外通过普通浏览器执行。真实回答 Runtime 在隔离声明语料上运行，与上述真实识别质量证据分开。

浏览器实际流程：

1. 打开 Inbox 单集 → 转写 → 逐字稿 → 人物与发言 → 重新识别。
2. 修改建议姓名并保存草稿，确认正文仍为旧姓名。
3. 刷新并重新进入，核对草稿恢复；确认后四段发言显示新姓名。
4. 单段编辑、解除匹配，核对其他段及原始文字保持。
5. @已确认人物提交问题，读取真实 Runtime 完成结果并核对引用原文。
6. 390px 窄屏打开核对面板与编辑弹层，测试焦点循环、Esc 取消及页面无横向溢出。

截图与本地测量保存在 `output/issue-346/`，不随 Git 提交；真实语料与 Runtime 原始产物保留在任务临时目录，没有复制进仓库文档。

| 场景 | 可观察结果 |
| --- | --- |
| 正常 | 识别生成草稿，保存不生效，确认才替换；真实浏览器完整流程通过。 |
| 慢请求 | 人物读取人为延迟 2 秒：逐字稿约 334ms 可读，人物响应约 2338ms 返回。识别进行中可阅读与取消，组件测试覆盖。 |
| 失败 | 识别请求人为延迟并返回 503：约 32ms 已确认原有正文仍可读，约 2048ms 显示失败；正文与已应用归属未变化。随后解除故障注入，正常读取成功。 |
| 首次访问 | 无人物结果时保留原 Speaker，读取和识别不阻塞正文；识别必须由用户主动触发。服务/组件测试覆盖未准备状态，刷新进入浏览器流程覆盖面板重建。 |

本次没有测量公网、TTFB 分布、带宽收益或生产长尾；它们不属于本功能的优化目标。失败状态采用明确的测试注入，不能当作真实服务故障率。
