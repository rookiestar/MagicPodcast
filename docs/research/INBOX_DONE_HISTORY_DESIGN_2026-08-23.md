# Inbox Done 与完成历史设计

状态：分阶段实施中（#169 已实现，#170 待实施）
日期：2026-08-23

关联：[领域词汇](../../CONTEXT.md)、[ADR-0006](../adr/0006-separate-done-from-action-queues.md)、[GitHub Spec #168](https://github.com/rookiestar/MagicPodcast/issues/168)

## 1. 结论

Inbox 是当前行动工作台，不是全部消费状态的总账：

- Inbox、Focus、Someday 是三条行动队列。
- Done 是当前完成状态，不是第四条可长期积累和排序的行动队列。
- 工作台保留第四栏，但改为有界的“最近完成”投影。
- 所有完成事实进入独立、可搜索、可继续加载的完成历史。
- “隐藏”只改变工作台可见性，不删除完成事实，也不新增 Archive 状态。

本设计固化产品、领域和验收边界。#169 已在源码中实现完成事实、最近完成和 15 秒撤销；独立完成历史仍由 #170 交付。真实数据库迁移与生产部署仍需另行授权。

## 2. 当前问题

截至本设计核对的 `origin/main`：

- 四种 `queue_state` 为 Inbox、Focus、Someday、Done，Done 与前三者使用相同队列读取和持久排序机制。
- 每条队列读取当前会返回全部项目；Done 没有时间窗口、数量上限或历史分页。
- 消费状态只保存当前队列和更新时间；单集离开 Done 后，过去的完成事实不会独立保留。
- 已读、进行中和不感兴趣已有独立语义，Done 不应代替这些状态。

因此，长期问题不是四栏数量不均，而是把“未来行动”和“过去完成”建模为同类队列。

## 3. 领域模型

| 概念 | 定义 |
| --- | --- |
| 行动队列 | Inbox、Focus、Someday；表达当前投入意图，可手动排序。 |
| Done | 当前完成状态；表示用户已处理到足够程度，无需继续占用注意力。 |
| 完成事实 | 单集至少一次被明确标记 Done 的长期记录；每个单集一条。 |
| 最近完成 | 最近 168 小时内、最多 20 条、当前仍为 Done 的工作台投影。 |
| 完成历史 | 所有完成事实的独立可检索集合，可包含当前正在重新处理或已标记不感兴趣的单集。 |
| 撤销完成 | 15 秒内完整回退刚发生的 Done 操作。 |
| 重新处理 | 按当前意图把已完成单集放入行动队列，不抹去完成事实。 |

Done 不表示完整听完，也不等同于已读、不感兴趣或归档。

## 4. 状态变化

| 用户动作 | 当前状态 | 完成事实 | 最近完成 | 完成历史 |
| --- | --- | --- | --- | --- |
| 首次标记 Done | 变为 Done | 新建，记录最近完成时间 | 若在 168 小时窗口内则出现 | 出现 |
| 再次标记 Done | 变为 Done | 刷新最近完成时间 | 重新进入并置顶 | 保持一条 |
| 15 秒内点击撤销 | 恢复原队列和原位置 | 恢复撤销前状态；原先没有则删除 | 消失 | 恢复撤销前结果 |
| 拖出或菜单重新处理 | 进入所选行动队列 | 保留 | 消失 | 保留，并显示当前队列 |
| 标记不感兴趣 | 当前不在行动队列 | 保留 | 消失 | 保留，并显示当前状态 |
| 删除来源单集 | 删除 | 一并删除 | 消失 | 消失 |

只有明确的“撤销”完整回退完成事实。即使仍在 15 秒内，拖出或菜单移动也属于重新处理，不是撤销。

## 5. Inbox 工作台

### 5.1 四栏

工作台继续保留四栏，降低结构迁移成本：

1. Inbox
2. Focus
3. Someday
4. 最近完成

前三栏是行动队列；第四栏是视觉弱化的完成投影，应明确标注“最近 7 天”并提供“查看全部”入口。

### 5.2 最近完成范围

- 时间范围：从当前时刻向前连续 168 小时。
- 数量上限：20 条。
- 排序：最近完成时间倒序。
- 归属：只展示当前仍为 Done 的单集。
- 数量：栏头显示实际展示数，范围为 0–20。
- 溢出：168 小时内超过 20 条时，明确提示仍有未展示项目，并引导查看全部。

重新处理后的单集不会同时出现在行动队列和最近完成中，但完成历史仍保留。

### 5.3 拖放与替代操作

- 拖入最近完成任意位置即表示标记 Done，不支持卡片前后精确落点。
- 最近完成不支持同栏手动排序。
- 从最近完成拖入行动队列属于重新处理，可在目标队列精确放置。
- 现有菜单、详情面板和窄屏按钮继续提供等价操作。
- Done 继续要求用户明确确认；打开原节目、已读或进行中不会自动完成。

## 6. 完成历史

### 6.1 入口与导航

- 从最近完成栏的“查看全部”进入独立完成历史视图。
- 不加入主导航，避免完成历史抢占行动入口。
- 返回 Inbox 后，原工作台上下文应保持可理解；具体滚动恢复属于实施验收。

### 6.2 内容与操作

- 每个单集只显示一条，按最近完成时间倒序。
- 显示单集、节目、最近完成时间和当前状态。
- 当前位于行动队列时，显示“曾完成 · 当前 Inbox/Focus/Someday”，主操作为定位当前队列。
- 当前不感兴趣时，显示“曾完成 · 当前不感兴趣”，可重新处理。
- 当前仍为 Done 时，可选择 Inbox、Focus 或 Someday 重新处理，默认目标为 Inbox。
- 完成历史入口显示全部完成单集数；口径为完成事实的唯一单集数。

### 6.3 搜索与加载

- 首期只搜索单集标题和节目名称。
- 搜索由服务端覆盖全部完成历史，不只过滤已加载页面。
- 初始加载 50 条，之后继续加载。
- 首期不做标签筛选、日期筛选、统计、批量操作或完成事件流水。

## 7. 撤销完成

- 标记 Done 成功后提供 15 秒“撤销”。
- 撤销恢复原行动队列和原位置，并恢复该操作发生前的完成事实。
- 撤销上下文只属于当前页面会话；刷新或超过 15 秒后改走重新处理。
- 若原队列或相关顺序已被其他设备修改，撤销必须拒绝覆盖、刷新规范状态并引导重新处理。
- 不得因撤销冲突把单集静默插入错误位置。

实现可复用当前队列 revision 冲突契约，但必须让服务端能够原子核对并恢复队列位置与撤销前的完成事实；具体 API 形态不在本设计中冻结。

## 8. 数据与服务边界

### 8.1 权威状态

- 当前行动归属继续由消费状态负责。
- 完成事实独立于当前行动归属，每个 `episode_id` 最多一条。
- 完成事实至少保存 `episode_id` 与最近完成时间，并随来源单集删除。
- 标记 Done 时，当前状态变化与完成事实新增或刷新必须在同一事务内完成。
- 重新处理只改变当前行动归属，不修改完成事实。
- 最近完成按当前 Done 状态与最近完成时间联合查询，不读取完整历史后再在前端截断。

不新增 Archive 状态，不建立完成事件流水，也不要求物理删除既有 Done 排序字段；既有 Done 位置和 revision 只是不再决定用户可见顺序。

### 8.2 历史读取

历史读取必须支持：

- 最近完成时间倒序；
- 单集标题或节目名称服务端搜索；
- 50 条首批和稳定的继续加载；
- 完成事实总数；
- 当前 Done、行动队列或不感兴趣状态的联合展示。

继续加载失败时，只标记失败页并保留已加载内容；重试不得清空当前结果或重复追加。

## 9. 旧数据迁移

实施需要新的版本化迁移，但真实数据库写入仍需单独授权。

- 只为迁移时当前仍为 Done 的单集建立完成事实。
- 最近完成时间使用其既有 `queue_updated_at`。
- 若发现当前 Done 缺少该时间，迁移预检应失败并报告，不用其他字段猜测。
- 历史上曾 Done、后来已进入其他状态的事实无法可靠重建，不做推断。
- 迁移后既有 Done 卡片按最近完成时间展示，不保留其旧手动排序。

## 10. 用户体验不变量

> 完成历史变慢、失败或继续加载失败时，Inbox 三条行动队列仍保持可见、可操作；已经加载的完成记录不会消失。

实施前须按性能专项模板确认以下结果：

| 场景 | 预期用户结果 |
| --- | --- |
| 正常请求 | 三条行动队列与最近完成正确出现；排序、计数和操作符合本设计。 |
| 慢请求 | 行动队列独立可用；最近完成或历史显示稳定加载态，不暴露错误空态。 |
| 请求失败 | 行动队列不受影响；最近完成或历史显示局部错误和重试，既有内容保留。 |
| 首次访问 | 无历史内容时先显示稳定加载态，确认成功为空后才显示真实空态。 |
| 缓存回访 | 若沿用缓存，应先保留上次成功内容并诚实提示刷新状态；本设计不强制新增缓存。 |
| 分页 / 滚动返回 | 已加载记录保留；失败页可单独重试，不重复追加。 |

实施验收必须同时记录 API 响应与有效内容出现时间；不能只证明请求更早返回。

## 11. 验收标准

### 11.1 领域与数据

- 当前 Done 与完成事实可独立表达。
- 重新处理、不感兴趣、重复完成、撤销和来源删除符合状态表。
- 每个单集最多一条完成事实；并发写入不产生重复。
- 旧数据只迁移可证明的当前 Done，迁移预检和回滚边界明确。

### 11.2 工作台

- 第四栏显示最近 168 小时、最多 20 条、当前仍为 Done 的单集。
- 最近完成按时间倒序，不支持同栏排序。
- 拖入任意位置完成；拖出可精确重新处理。
- 15 秒撤销能恢复原队列、原位置和撤销前完成事实；冲突不静默覆盖。
- 三条行动队列的持久顺序、Focus 上限、详情、菜单、已读和进行中语义不回归。

### 11.3 完成历史

- 从最近完成进入独立历史，主导航不新增入口。
- 服务端搜索覆盖全部历史，初始 50 条并可继续加载。
- 当前状态、总数、排序、重新处理和定位当前队列准确。
- 正常、慢、失败、首次访问及分页失败均符合用户体验不变量。

### 11.4 验证边界

实施完成后至少需要：

- 后端迁移、状态变化、最近完成、历史搜索/分页、并发与冲突测试；
- 前端工作台、拖放、15 秒撤销、历史页、慢请求、失败、首次访问和分页保留测试；
- 桌面、iPad 横屏、iPad 竖屏和手机真实界面验收；
- 定向与全量前后端检查、类型检查、lint、生产构建和文档链接检查；
- 使用 [性能专项验收模板](../optimization/PERFORMANCE_ACCEPTANCE_TEMPLATE.md) 记录有效内容时间、失败保留与分页结果。

数据库迁移 apply、提交、推送、部署和生产验收均不在本设计任务授权内。

## 12. 不在首期范围

- Archive 状态或手动归档动作；
- 完成事件流水、完成次数、首次完成时间或统计看板；
- 标签、日期筛选和批量操作；
- 最近完成同栏排序；
- 在主导航增加完成历史；
- 自动推断无法重建的旧完成事实；
- 自动执行数据库迁移、提交、推送或部署。
