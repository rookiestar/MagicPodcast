## 交付范围

- 使用现有受限 Runtime 识别本集人物、昵称与发言归属；保留原文身份依据，处理 HTML Show Notes，阻止缺少身份信息的跨集同名合并。
- 人物身份与出场关系、片段归属、用户确认分别持久化。纠正可以覆盖前一次纠正；仅同一来源版本且原文、说话人仍匹配时复用片段确认，新版本即使三者相同也不复用旧纠正，旧确认记录保留。旧版出场关系不作为当前候选。
- 独立内容检索模块支持人物过滤和一般内容检索，输出原文、来源版本、定位、节目/单集标题及覆盖状态。现有全站搜索入口未改写。
- 当前单集与库内历史先检索，再判断证据是否覆盖问题；不能仅凭一个主题词命中跳过历史或判定问题已回答。必要时有界网页补搜，最终生成阶段关闭工具。
- 网页材料要求作者、身份依据、可核对原文和实际读取标记；只见摘要或身份无法核对的材料不计入人物观点。实际网页工具入口已修复，其他高权限工具保持关闭。
- 模拟回答明确标注非本人回复，区分原有表达与推演；引用限定于已召回的本人原文，背景不能冒充观点，节选缺失不能推断整篇原文没有该内容。
- @单人选择、中文输入法/键盘、姓名确认、片段确认与撤销、既有转写显式准备、来源跳转、四态与取消均已接入。普通问答不会显示人物检索；未调用网页搜索时显示“未执行”。
- 原文换版、删除、归属变化和 Show Notes 修改使失效证据退出查询。Show Notes 更新通过数据库触发器使派生索引失效并提示重新识别，人工确认记录不删除。
- Schema 27/28、迁移合同及 Snapshot 脱敏适配完成。Snapshot v10 移除人物私有事实与转写派生副本，沿用既有加工产物图脱敏原则。

## 关键修复依据

接手后新增反例证明：同名但无身份依据的人被跨集合并；第二次片段纠正可能被第一次记录覆盖；待确认状态在重提取后可能变成已确认；旧纠正可能被套到新版同序号片段。对应回归已修复并通过。

现有加工发布回调不能覆盖所有 Show Notes 更新路径，单靠 `current` 标记也不能排除已失效的源数据。因此在共享检索入口校验当前来源与归属，并为 Show Notes 更新增加一次派生数据失效处理。该处理不重建数据、不覆盖原文、不删除人工确认。迁移 DDL 识别器补充触发器目标表识别，仍拒绝未声明目标表，没有放宽迁移安全门禁。

## 实际 Runtime 与真实资料

只读查询生产源库确认当前共有 **8 集**有效成功转写，全部纳入隔离评估。它们不是合成样本，也没有因此写入生产库。

- 实际 Runtime 对 8 集执行人物识别，共产生 17 个有定位依据的人物候选；处理 1,668 个片段，其中 1,610 个得到归属，58 个保留未归属。上述数量是处理覆盖统计，**不是全量人工标注后的准确率**。
- 单集识别耗时约 18–79 秒。未知身份/未归属内容仍可用于一般检索，不作为人物观点。
- Kevin Ding、逯雨鑫、曾鸣三道实际人物问题走隔离 HTTP → 共享检索 → 实际 Runtime；核对关键断言及其引用。首次复核发现背景细节引用不精确，收紧证据提示后重新生成三题并复核。该轮重用先前实际识别产物，没有冒充重新运行身份模型。
- 实际 Runtime 的库内充分题、不相关问题补搜/无法判断题通过。无法判断不靠模型记忆补造人物立场。
- 网页能力验证实际搜索并打开 Paul Graham 的原始文章，返回的原文句子与独立读取页面一致；随后通过合成单集的完整人物问答 HTTP 路径取得 [原始文章](https://www.paulgraham.com/makersschedule.html) 的 E1 引用。该网页测试使用真实网页与真实 Runtime，单集明确为测试记录，不冒充真实播客。
- 网页配置依据参考 [官方配置说明](https://developers.openai.com/codex/config-reference/)，实际工具可用性以本项目固定 SDK 的运行活动与原文读取结果为准。

原始评估材料和截图位于本机 `/tmp/persona324-takeover/`，未纳入仓库。`real-final` 为实际人物识别与初始问答记录，`answer-final` 为修订后的实际问答，`native-final` 为实际 Runtime 分支验证，`web-capability-final` 为真实网页完整路径。该目录不是运行或部署依赖。

## 交付边界

原计划的 10–20 集、约 30 题是建议规模；实际可用真实成功转写只有 8 集，未制造更多样本。真实语料不存在足够的同人跨集重复样本，跨集身份与纠正边界同时使用可核对合成反例验证。当前结果不承诺普遍识别准确率或统一响应时长。

生产启用仍需独立完成版本化迁移、既有产物的人物/索引准备、发布及生产健康检查。既有单集可经人物准备入口处理，不必重新转写。Git 提交、推送、合并、关票及生产写入仍遵循项目授权门槛。
