# 领域文档

MagicPodcast 采用单一领域上下文。前端、后端、工作流、部署和数据维护共同服务同一个个人播客管理产品，使用同一套领域语言和架构决策。

## 探索代码前

相关工程技能在探索代码前应按需读取：

- 仓库根目录的 `CONTEXT.md`，作为统一领域术语入口。
- `docs/adr/` 中与当前任务相关的架构决策记录。
- `README.md`、`docs/README.md` 以及 `AGENTS.md` 规定的任务专项文档。

如果 `CONTEXT.md` 或 `docs/adr/` 尚不存在，应正常继续，不把补齐这些文件作为任务前置条件。只有在真实术语或架构决策需要沉淀时，再通过相应技能创建。

## 使用规则

- Issue、PRD、测试名称和架构建议应优先使用 `CONTEXT.md` 中定义的术语。
- 不为同一概念随意创造同义词；发现术语缺口时，应明确记录并考虑补充领域文档。
- 如果新方案与已有 ADR 冲突，必须明确指出冲突和重新决策的理由，不能静默覆盖。
- 当前源码、测试和运行结果优先于历史总结；归档文档不直接作为当前实现依据。
