## 修复原则

1. 修复前必须先备份。
2. 每一步先 dry-run，输出候选数量和候选 ID。
3. 不做盲目替换，不做批量删除。
4. 优先从原始 Feed 重新抓取，尽量不用猜测方式补数据。
5. 修复时只碰机器字段，保留 `my_rate`、`notes` 等人工字段。
6. 修复后重新跑完整体检，确认结构、数量、重复项和核心统计没有变坏。
