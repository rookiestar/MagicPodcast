# MagicPodcast 重构路线图

最后更新：2026-05-16

## 背景

未来两个月仍以自用为主，但不排除后续扩大范围。当前优先级是播客管理体验和工作流能力升级；UI 可以接受重做；AI 目前是锦上添花；数据非常珍贵，需要建立备份恢复流程；长期方向是服务化部署，并和 CLI、个人知识管理体系、OpenClaw/个人助理进一步融合。

## 阶段 0：地基整理

目标：让项目可验证、可备份、可恢复、可安全迭代。

已完成的第一批动作：

- 建立数据库验证、备份、恢复脚本。
- 修复健康检查误报。
- 统一启动、停止、重启入口。
- 修复同步测试对外部网络的依赖。
- 修复搜索单集分页问题。
- 恢复前端构建时的类型和规范检查。

下一步建议：

- 为备份增加定时任务。
- 梳理所有脚本入口，保留少数官方入口，其余归档。
- 把数据库迁移、备份、恢复放进同一个发布前检查清单。
- 为关键接口补最小集成测试：搜索、同步、标签、工作流执行。

## 阶段 1：播客管理体验升级

目标：把“能管理”升级为“管理很顺手”。

建议范围：

- 播客列表支持更强筛选：订阅状态、更新时间、未处理数量、标签、同步状态。
- 单集列表支持队列化：待读、待读完、已处理、已归档、重要。
- 支持批量操作：批量打标签、归档、加入工作流、重新同步。
- 明确同步状态：最近同步时间、失败原因、下次重试、失败次数。
- 建立“播客详情页”的真实工作台：信息、单集、标签、历史报告、相关工作流集中展示。
- 增加安全删除和恢复体验，避免误删真实数据。

优先级最高的用户路径：

1. 我今天应该看哪些新内容。
2. 我如何快速判断一个播客是否值得继续订阅。
3. 我如何把一批单集送进同一个工作流。
4. 我如何看到同步失败和处理结果。

## 阶段 2：工作流能力升级

目标：让工作流从“功能模块”变成可依赖的自动化系统。

建议范围：

- 工作流模板化：摘要、选题、知识卡片、长文草稿、待办提取。
- 增加 dry-run：执行前预览输入范围和预计动作。
- 增加执行历史：输入、输出、耗时、错误、重试记录。
- 增加队列视图：待执行、执行中、成功、失败、可重试。
- 增加报告版本管理，避免覆盖有价值输出。
- 报告展示层做安全渲染，降低富文本内容带来的风险。

优先级最高的用户路径：

1. 我能放心把一批单集交给工作流处理。
2. 我能清楚知道每次自动化做了什么。
3. 出错后我能重试，而不是重新配置一遍。

## 阶段 3：CLI 与个人知识系统融合

目标：让 MagicPodcast 成为个人系统里的可调用能力。

建议范围：

- 提供稳定 CLI：搜索、同步、导出、运行工作流、查看状态。
- 增加机器可读输出：JSON、Markdown、frontmatter。
- 增加导出管道：Obsidian、Logseq、Notion、纯 Markdown 文件夹。
- 提供本地事件或 webhook：同步完成、工作流完成、报告生成。
- 为 OpenClaw/个人助理准备稳定 API：查询播客、查单集、触发工作流、获取报告。

优先级最高的用户路径：

1. 我可以在终端搜索播客资料。
2. 我可以从个人助理触发一次同步或工作流。
3. 我可以把结果自动进入个人知识库。

## 阶段 4：长期服务化部署

目标：把本地个人工具升级为长期运行的个人服务。

建议范围：

- 明确部署形态：本机常驻、NAS、VPS、Docker。
- 增加配置分层：开发、本地长期运行、生产。
- 增加基础鉴权，先服务个人安全使用。
- 增加任务调度与失败告警。
- 增加数据库迁移纪律和回滚方案。
- 增加备份异地保存。

暂不建议过早投入：

- 多用户权限模型。
- 大规模社交化功能。
- 过重的微服务拆分。
- 全量重写。

## 决策原则

1. 真实数据优先：任何会改写大量数据的需求，先有备份和回滚。
2. 工作流可追踪：任何自动化都要能看到输入、输出和失败原因。
3. CLI 优先稳定协议：先把输入输出约定稳定，再追求花哨体验。
4. UI 可以重做，但不要一次性重写全部页面。
5. 先围绕每天真实使用路径优化，再做长期架构升级。
