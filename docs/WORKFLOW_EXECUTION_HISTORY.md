# 工作流执行历史说明

最后更新：2026-05-31

本文记录当前工作流执行历史页的实际行为。旧的“执行历史详情查看”设计草案已移入 [archive/planning/JOB_EXECUTION_DETAIL_DESIGN.md](archive/planning/JOB_EXECUTION_DETAIL_DESIGN.md)，只保留追溯用途。

## 当前行为

- 工作流详情页默认不加载执行历史，只有切换到“执行历史”标签时才请求任务列表，避免拖慢详情首屏。
- 执行历史列表默认使用摘要视图，展示触发方式、状态、执行时间、处理节目数、发现单集数、创建单集数、匹配数和错误数。错误数只统计 Feed/节目失败。AI 摘要成功时显示用量徽章；失败时显示「AI摘要失败」，任务仍可为已完成。
- 点击某条任务会按需请求任务详情；已加载过的任务详情会缓存在当前页面状态里，再次展开不会重复请求。
- 展开后会显示每个节目的执行记录，包括节目标题、RSS 地址、状态、耗时、发现单集数、新建单集数、匹配数和错误信息。
- 已完成任务可打开报告弹窗；未完成任务的报告入口保持不可用。
- 执行历史分页由接口返回的分页信息控制。

## 相关接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/v1/workflows/:id/jobs?page=1&page_size=10&view=summary` | 获取工作流执行历史摘要 |
| `GET` | `/api/v1/jobs/:id` | 按需获取单个任务详情和 `executions` |
| `GET` | `/api/v1/jobs/:id/report` | 获取已完成任务的执行报告 |
| `POST` | `/api/v1/jobs/:id/report/regenerate-summary` | 重新生成报告里的 AI 摘要 |

## 维护边界

- 执行历史的按需加载策略属于当前性能优化的一部分；改成首屏全量加载前，需要重新做页面性能巡检。
- 任务详情展开只影响当前页面状态，不改变后端任务数据。
- 报告弹窗依赖已完成任务，运行中或失败任务不应强行打开报告入口。
