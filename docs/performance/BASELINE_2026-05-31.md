# MagicPodcast 性能基线（2026-05-31）

本基线用于后续重构和优化对比。测试在本机已有服务上运行，前端为 Next.js 生产服务，后端为本地 Go API，数据库为本地 SQLite。生产模式通过 `./scripts/restart.sh --prod` 启动，后端为 release 模式，默认关闭数据库 SQL 调试日志。

## 验证入口

```bash
# 质量检查
(cd backend && go test ./...)
(cd backend && go vet ./...)
(cd backend && go test -race ./internal/services)
(cd frontend && npm run type-check)
(cd frontend && npm run lint)
(cd frontend && npm run test:run)
(cd frontend && npm run build)

# 页面/API 轻量性能巡检
node scripts/performance-audit.mjs \
  --base-url http://localhost:3000 \
  --api-url http://localhost:8080 \
  --runs 3 \
  --strict

# 后端并发基准
(cd backend && BENCHMARK_DURATION=5s BENCHMARK_WORKERS=10 go run ./cmd/benchmark)

# 搜索服务微基准（不依赖本地真实数据库）
(cd backend && go test ./internal/services -run '^$' \
  -bench 'Benchmark(SearchService|TextProcessing|RelevanceCalculation)$' \
  -benchtime=10x -count=1)
```

## 当前瓶颈

- 搜索仍是当前最值得继续优化的接口：重启后第一跳仍可能超过 500ms，默认预热后平均 126.9ms、P95 127.2ms，并发压测下 P95 为 187ms。继续优化查询排序、缓存或返回策略前，需要先确认搜索结果顺序是否允许变化。
- 页面资源体积集中在 648KB 到 752KB，暂未超过当前告警阈值，但播客详情、播客列表和工作流详情仍是后续资源瘦身重点。
- 后端并发基准整体成功率为 100%，可以作为后续重构的功能不退化参考。
