## Problem Statement

Focus Detail 顶部把转写状态、开始加工与查看内容混在一起。完成后「查看转写」重复了转写 Tab，并随当前 Tab 显隐；将加工操作移入正文后，原操作栏又只剩两个按钮，形成低密度空行。用户已批准：稳定入口、操作归位正文、合并低密度栏位，审美第一。

## Solution

- 始终显示 `Show Notes｜转写｜笔记`，包括首次读取、未转写和失败时；进入详情仍默认 Show Notes。
- 删除顶部独立转写状态与开始/查看转写按钮，取消整条独立操作栏。
- 桌面：导航左对齐；「原节目 ↗」「当前行动队列/Done⌄」右对齐，与导航共用一行。两组使用留白区分，不增加竖线或底色。
- 手机：原节目与当前队列按钮归入标题下元信息区域；三个 Tab 独占下一行。内容拥挤时元信息自然换行，不缩小点击区域。
- 队列按钮使用浅描边和纸色背景；正文「开始转写」为主要黑色按钮。标题和正文保持原有舒展排版，通过取消冗余栏位增加首屏正文空间。

### 转写 Tab 状态原型

| 情况 | Tab 表达 | 正文与行动 |
| --- | --- | --- |
| 首次读取 | 固定入口，不提前判定未转写 | 仅转写区域显示读取中；单集身份和其他可读内容保留 |
| 未转写且在 Focus | 普通「转写」 | 「把这期节目，变成可回看的文字」；「生成总结、纪要与逐字稿」；黑色「开始转写」按钮 |
| 未转写且不在 Focus | 普通「转写」 | 「加入 Focus 后可开始转写」；通过现有队列菜单切换，不能直接开始或自动入 Focus |
| 加工中 | 低调进度标记＋可访问状态名称 | 真实当前阶段及「你可以继续阅读 Show Notes」；不虚构百分比或剩余时长；已有成功产物继续可读 |
| 已有可读产物 | 普通「转写」，无成功角标 | 按现有产物能力显示总结、纪要、逐字稿；不增加「查看转写」 |
| 失败 | 克制异常标记＋可访问状态名称 | 就近显示原因和既有可执行恢复动作；有旧产物时继续阅读 |
| 已取消/不可重试 | 不伪装成进行中或完成 | 显示真实状态与现有允许的操作；不能把所有失败统一做成可重试 |

完成不自动切换 Tab；只在当前详情会话观察到加工从进行中转为完成时给一次非阻塞「转写已完成」提示。打开已完成单集、轮询、切 Tab 均不重复提示。

## User Stories

1. As a 阅读者, I want 单集标题与正文成为视觉中心, so that 控件不会抢占注意力。
2. As a 用户, I want 所有状态下都有固定转写入口, so that 不必等待 Tab 出现。
3. As a 首次访问者, I want 默认阅读 Show Notes, so that 打开详情不会触发加工。
4. As a Focus 用户, I want 在转写正文看到开始按钮, so that 操作与结果位于同一处。
5. As a 非 Focus 用户, I want 知道开始加工的条件, so that 不会误以为功能失效。
6. As a 用户, I want 加入 Focus 仍遵循现有限额确认, so that 操作不会绕过约束。
7. As a 加工中的用户, I want 看见真实阶段, so that 不会被虚构进度误导。
8. As a 阅读者, I want 加工期间继续查看 Show Notes 和笔记, so that 等待不阻断阅读。
9. As a 用户, I want 完成后留在当前 Tab, so that 阅读不被打断。
10. As a 用户, I want 完成提示仅出现一次, so that 轮询不会产生噪声。
11. As a 已完成单集的用户, I want 从转写 Tab 直接阅读知识产物, so that 不需要重复查看按钮。
12. As a 加工失败的用户, I want 原因和恢复动作出现在转写内容旁, so that 能直接处理问题。
13. As a 已有旧产物的用户, I want 新加工失败时继续阅读旧产物, so that 已有成果不消失。
14. As a 用户, I want 取消和不可重试状态有准确解释, so that 不会执行无效动作。
15. As a 桌面用户, I want 导航与次级操作共用一行, so that 首屏容纳更多正文。
16. As a 手机用户, I want 三个 Tab 有独立空间, so that 导航不会被右侧操作挤压。
17. As a 用户, I want 队列菜单直接显示当前位置, so that 可以清楚判断当前投入意图。
18. As a Done 用户, I want 重新处理仍保留完成事实, so that 视觉调整不改变历史语义。
19. As a 用户, I want 原节目入口保留安全打开与失败恢复, so that 合并栏位不损失功能。
20. As a 键盘用户, I want 导航、菜单、开始与重试均可操作, so that 不依赖鼠标。
21. As a 辅助技术用户, I want 状态与焦点有文字和语义表达, so that 不依赖颜色识别。
22. As a 长文阅读者, I want 切回各 Tab 时保留阅读位置, so that 不丢失上下文。
23. As a 逐字稿用户, I want 吸顶播放器与导航互不遮挡, so that 当前段落仍可阅读。
24. As a 用户, I want 单集助手打开关闭后保留当前 Tab 与阅读位置, so that 查询后可以继续阅读。

## Implementation Decisions

- 范围是 Focus Detail 的入口与响应式布局；复用现有 ConsumptionDetailPanel、EpisodeProcessingPanel 与队列菜单行为，不增加后端、数据库字段或加工状态机。
- 外层转写 Tab 不再由运行或产物存在与否决定是否显示。内部总结/纪要/逐字稿仍按真实能力显示，保留现有默认子视图，不强制默认逐字稿。
- 加工动作归 EpisodeProcessingPanel 正文管理，沿用现有开始、重试、重新同步、旧产物重新转写、取消及未知外部结果的操作限制。完成态低频维护操作放在现有运行详情区域，不能因移除顶部按钮而丢失。
- 正常、慢请求、失败和首次访问的用户可见结果按上表执行，这是本次批准范围；请求时序、缓存、超时、重试策略及资格合同保持现有行为。
- 桌面导航与操作在视觉上共行，但原节目与队列按钮不能成为 tablist 的 tab；保持独立交互语义。手机复用同一组操作，不能渲染两组可聚焦副本。
- 保留原节目缺失/拒绝、安全打开、写入失败恢复，及队列保存中、失败恢复、Focus 限额、Done 完成事实语义。
- 视觉沿用暖纸色、墨色、少量橙色、方角、细规则线；不新增玻璃、渐变、厚阴影、卡片堆叠。保持至少 44px 点击热区和清晰焦点。
- 删除独立操作栏及冗余分隔线，不以缩小正文、标题、隐藏元信息或降低可用性提高信息密度。长标题、长作者、不同队列标签须自然布局。
- 保留各 Tab 阅读位置、单集切换重置和助手往返恢复；结合真实吸顶高度验证播放器、菜单和当前段落，不能沿用错误固定偏移导致遮挡。
- 本次最终原型取代上一轮三栏图片中保留的独立操作栏；图片中的播放器造型、虚构 speaker 文本、居中图标仅为草图，不是新增改造需求。

## Testing Decisions

- 主要验收接缝为现有 Focus Detail 用户流：真实详情及加工子树，仅模拟公开 API 和媒体事件。复用现有详情、Inbox 用户流和播放器测试，不新增平行测试框架。
- 好测试验证入口、可读内容、状态、请求次数、可执行动作、焦点和阅读位置，不断言内部组件结构或私有状态。
- 覆盖上表全部状态；初次读取、慢响应、失败、完成均保留三个固定 Tab。点击 Tab 不开始加工，点击开始只发送一次既有请求，非 Focus 不越权。
- 验证后台完成不切外层及内层 Tab；完成提示只针对当前单集的实际状态转换，不在首次载入或轮询中重复。
- 验证旧产物阅读、真实重试限制、旧产物维护操作、原节目安全打开、队列移动/失败/限额、Done 与助手往返仍可用。
- 通过已授权的浏览器路径验收桌面 1258px/1440px 与手机 390px：桌面只有一行导航和次级操作；手机导航独占一行；长文、长标题、菜单展开、状态变化无横向溢出、遮挡或布局跳动。
- 同一窗口及同一内容前后比较：取消操作栏后首屏正文上移，标题和正文排版不被压缩；同时检查键盘遍历、菜单边界、至少 44px 热区和非颜色状态表达。
- 执行当前仓库要求的受影响测试、类型检查、lint 和构建；已有仍覆盖当前实现的通过证据可以复用，仅针对新改动、失败和未解决风险扩大验证。
